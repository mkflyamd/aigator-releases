| `H_Prompt_injection_leading_to_unintended_d_04` | Prompt injection leading to unintended destructive actions | **Implemented (macOS/Linux not exercised)** | [design](../superpowers/specs/2026-10-07-prompt-injection-controls-design.md) / [plan](../superpowers/plans/2026-10-07-prompt-injection-controls.md) | Writes were already drafts that need a human approve click (HITL gating on send/create/delete); this work adds controls inside the agent loop. (1) `execute_tool` validates model-supplied inputs against the tool's registered schema and returns `invalid_tool_input` so the model can retry; a missing or unsupported schema fails open (logged, never blocks the tool). (2) Tool allow-list: a call to a tool that was not offered to the loop is rejected with `tool_not_offered`. (3) First-use card per data source per tab ("Allow for this tab" / Deny), covering every tool of Outlook mail, calendar, contacts, the people directory, Teams, SharePoint and OneDrive, OneNote, Jira, Confluence, Slack, GitHub, each MCP server, and each website host `fetch_webpage` opens (the website card shows the address, cut at 200 characters). An unanswered card expires after 5 minutes and counts as a denial (the time spent waiting is not counted as the model going silent, and the card offers "Ask again"); the approval ends when the tab closes and is never saved. This card is also the confirmation for search and cross-system access. (4) Results from outside sources (every tool with a data source, web fetch and search, and the browser tools) get an untrusted-content notice, a pattern filter removes override phrases, "new instructions:", instructions aimed at the assistant to send or fetch, and markdown images carrying data in the URL (with a toast and a log line), and the system prompt has a matching rule that tool results are data, never instructions. (5) `fetch_webpage` refuses URLs whose path and query together (measured on the request target `urllib` sends, so `;params` count and a fragment does not) are over 300 characters, and checks every redirect hop. (6) `schedule_task` shows a per-call confirm card in a tab (every field is cut and cleaned, and the prompt is shown only up to 300 characters; nothing is created until Allow; Deny or no answer in 5 minutes creates nothing) and is refused in unattended runs. Limits: acceptance criterion 4 (content filters block exfiltration instructions "effectively") is only partially met, because a pattern filter cannot prove content is safe, can miss rephrased attacks and can remove a harmless sentence; marking and filtering reduce prompt injection but do not remove it. The allow-list is the set of tools offered for the request, not a list the user edits. The allow-list is the offered set and the model can widen it by naming skills that are not gated, so the source card, not the allow-list, is the boundary for reaching data. An approved source stays readable for the rest of the tab. `web_search` queries are not gated. The URL guard narrows but does not close data leaving in a URL: once a host is approved for a tab, up to 300 characters of path and query per request can still leave, and a redirect to a different host gets the length check but no new-host card. `fetch_webpage` blocks no address (internal sites and localhost are reachable): the report does not ask for an address block and internal sites are a required use case. Scheduled and background runs have no screen, so they skip the source card (the allow-list still applies); a schedule the user approved runs without further cards, with the skills it lists (a job with none lets the run infer skills from its prompt). Direct skill-router intents (user-typed shortcuts) call tools without the card, and their data is marked untrusted and filtered. IDN and look-alike hosts are shown as written. Requests with no context id share one "default" approval bucket. Follow-up, not done: the browser confirm route `/api/browser/confirm/{id}` is not CSRF-guarded and relies on the confirm id staying secret. Likewise none of the mutating scheduler routes (create, update, delete, pause, resume, run-now under `/api/scheduler/jobs`) has a CSRF guard; follow-up, not done. Data can still leave in the DNS lookup of an already approved host name (up to about 250 characters per lookup). A short follow-up in a chat keeps the skills of tools that actually ran earlier in that chat (read from the server-side store; refused calls do not count), so "now try X" still gets the same tools; a skill is not turned on merely because the model called one of its tools. Not exercised on macOS or Linux. |

## Process

Each High finding gets its own brainstorming → spec → implementation-plan → implementation cycle:

1. Design spec written to `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`, aligned to the
   report's exact remediation steps and acceptance criteria for that finding.
2. Spec approved by the team.
3. Implementation plan produced (`writing-plans` skill).
4. Implementation + tests land on `security/threatmodel-remediation`.
5. This table is updated with status + links.
